# Каталог через RSC, RTK Query только для заказов

**Status:** accepted

Спека предписывала тянуть каталог (товары/отзывы) на клиенте через RTK Query. Мы читаем каталог в Server Components, а RTK Query (и Redux) оставляем только для заказов (создание/оплата/трекинг).

## Почему

- Каталог — read-only статика: RSC отдаёт его мгновенно, без клиентского JS, с SEO. Клиентский RTK Query для статичного каталога — антипаттерн в App Router.
- RTK Query получает честное оправдание: он обслуживает единственный реально интерактивный server-state — заказы.

## Consequences

- Единая серверная функция `getProducts()` — точка доступа к данным. RSC зовёт её напрямую; route handlers `/api/products*` остаются как публичный REST поверх неё. RSC НЕ ходит в собственные route handlers по HTTP (лишний хоп).
- Redux/RTK Query монтируются только там, где нужны заказы.
