# SQLite + Drizzle как хранилище данных

**Status:** accepted

Спека допускала моковые данные и хранение заказов в Zustand/localStorage. Мы вместо этого делаем заказы и каталог реальным server-state в SQLite (на персистентном диске VPS/Docker), доступ — через Drizzle + better-sqlite3.

## Почему

- Заказ — транзакционная сущность; localStorage как «источник истины» по заказу не выдерживает вопроса на собеседовании. Реальная БД даёт честное разделение server-state (RTK Query) и client-state (Zustand).
- Единый слой данных: каталог сидится в те же таблицы, `reviews → products` через FK, можно показать схему и JOIN.

## Considered Options

- **Vercel + файловый SQLite** — отклонено: эфемерная read-only ФС, файл БД не переживёт холодный старт. Деплой только VPS/Docker с персистентным диском.
- **Prisma / Sequelize** — Prisma тяжелее (codegen, рантайм); Sequelize слабее всех в TS и провоцирует `any`, что прямо нарушает правило проекта. Drizzle даёт типобезопасность из коробки и синхронный драйвер.

## Consequences

- Деплой ограничен средой с персистентным диском (не Vercel serverless).
- Нужен seed-скрипт для каталога.
